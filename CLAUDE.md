# Контекст проекта для Claude

Сайт для генерации и редактирования картинок моделью Qwen-Image-2.1 на арендованном сервере RunPod.
`app.py` — сайт (Gradio), `setup.sh` / `start.sh` — установка и запуск, `README.md` — установка для человека,
`RUNPOD.md` — как заканчивать работу, начинать снова и выбирать видеокарту. Основная ветка:
`claude/qwen-image-setup-j83x0r` (по ней ставится сервер, изменения попадают туда через PR).

Пользователь — новичок, пишет по-русски. Отвечать по-русски, просто, без жаргона.

## Правила пользователя (обязательно)

- **Спрашивать перед любыми тратами**: выбор видеокарты, создание пода, большие пачки генераций.
  Удалять под только после того, как пользователь написал, что всё скачал.
- **Без постоянного диска**: Container Disk 80 ГБ, Volume Disk 0. Stop стирает всё, поэтому в конце работы:
  скачать картинки → Terminate. Следить за балансом: при $0 RunPod удаляет под вместе с файлами.
- **Только 2K, 40 шагов, CFG 1.0.** Не тратить генерации на тесты количества шагов.
- **Фон удаляем через Qwen** (галочка «Прозрачный фон»). Отдельная модель BiRefNet не подошла по качеству.
- **Не запускать много генераций без спроса.** Обычно: 5 вариантов на персонажа; точечная правка — 1–2 попытки.
- **Выражения лиц только весёлые или праздничные**, не хмурые и не злые.

## Сервер

- Лучшее соотношение скорости и цены — RTX PRO 6000 WK (~$1.7/ч, картинка 2K ~1 мин). Дешевле в час — A40.
  Подробные замеры — в `RUNPOD.md`.
- Шаблон `runpod/pytorch:1.0.2-cu1281-torch280-ubuntu2404` требует CUDA 12.8+: при создании пода через API
  передавать `allowedCudaVersions: ["12.8", "12.9", "13.0"]`, иначе может достаться машина со старым драйвером.
- Порты: `8888/http` (Jupyter), `7860/http` (сайт), `22/tcp`. Пароль Jupyter — новый для каждого пода,
  через переменную `JUPYTER_PASSWORD`.
- Ключ RunPod хранится у пользователя в переменной окружения `RUNPOD_API_KEY`. Никогда не просить его в чат
  и не записывать в репозиторий.

## Генерация из скрипта

На поде сайт доступен как `http://127.0.0.1:7860`, его можно вызывать через `gradio_client`:

```python
from gradio_client import Client, handle_file
client = Client("http://127.0.0.1:7860")
img_path, seed = client.predict(
    prompt,
    [{"image": handle_file("ref.png"), "caption": None}],  # до 10 картинок
    "Как у последней картинки",  # или "Как у первой картинки", или "1:1", "3:4", ...
    True,       # прозрачный фон
    seed, False,  # seed, случайный seed
    40, "", 1.0,  # шаги, негативный запрос, CFG
    api_name="/edit_image",
)
```

Генерация по тексту: `api_name="/text_to_image"`, аргументы `prompt, aspect, transparent, seed, randomize_seed,
steps, negative_prompt, cfg`. Все результаты сайт также сохраняет в `/workspace/outputs`.

## ComfyUI (по желанию)

`comfy/setup.sh` ставит ComfyUI (версия зафиксирована) в `/workspace/ComfyUI` с моделью в bf16 из
`Comfy-Org/Qwen-Image-2.1` (пользователь хочет именно полное качество, не int8) и помощником для запросов (PE,
только int8). `comfy/start.sh` запускает его на порту 8188, картинки идут в `/workspace/outputs/comfy`.
`comfy/workflows.py` делает из официальных шаблонов Comfy готовые схемы (bf16, 2K, 40 шагов) и кладёт их в
`ComfyUI/user/default/workflows`. Схемы проверены в интерфейсе ComfyUI без видеокарты (все блоки и связи,
проверка сервера); **на видеокарте ComfyUI ещё не запускался** — при первом запуске проверить скачивание,
генерацию и прозрачный PNG на выходе. Особенности:
- `LoadImage` в ComfyUI отбрасывает прозрачность (альфа уходит в MASK), поэтому схемы вставляют
  `JoinImageWithAlpha` перед блоком Qwen — иначе прозрачный образец персонажа виден модели с чёрным фоном.
- Размер 2K задаёт `resolution: 2048` у блока Qwen (образцы приводятся к ~4 Мп, результат того же размера).
- Помощник для запросов (`refine_prompt`) включён во всех схемах — так хочет пользователь. Если персонаж теряет
  сходство с образцом (помощник назвал его видом животного), первым делом выключить `refine_prompt`.

## Персонажи: что работает в запросах

Пользователь делает наборы персонажей в стиле «Холодного сердца» (акварель, прозрачный фон) по своим образцам
(на ПК пользователя лежат в папке `refs/` проекта, в GitHub не попадают):
по 5 вариантов поз на персонажа.

- **Называть персонажа только «the character from image 1».** Не называть вид животного (lizard, salamander,
  reindeer, snowman…) и не сравнивать с другими животными («like a cat»). Иначе модель рисует обычное животное
  вместо персонажа: для ящерицы-саламандры «salamander lizard» дал просто ящерицу, «like a waking cat» — кошку.
- **Новая поза** — этот запрос дал лучшие результаты:
  `Draw the character from image 1 in a completely new pose: {pose}. Change the pose and body position, but keep
  the same face, hair, outfit, colors and soft watercolor illustration style. Full body, a single isolated
  character, no other objects.`
  Без «completely new pose / Change the pose» модель копирует позу образца.
- **Разные выражения лица**: добавить `Give the character a clearly different facial expression than in image 1:
  {expression}.` Иначе у всех вариантов то же лицо, что на образце. Выражения — только весёлые или праздничные.
- **Точечная правка** (пальцы, руки, предмет): нарисовать на картинке красный эллипс (толщина линии ~12 px) и
  написать `Fix only the area inside the red circle: {что исправить}. Remove the red circle. Keep everything else
  in image 1 exactly the same: the same character, pose, face, expression, colors, soft watercolor illustration
  style and composition.` Одна правка — 1–2 попытки с разными seed.
- **При точечной правке давать только одну картинку.** Если добавить вторую как образец, модель перерисовывает
  всю картинку по ней. Ориентир внутри той же картинки работает: руки Олафа стали тонкими по запросу «as thin as
  the twigs of his hair».
- **Рога оленя** правками по месту выходили не такими, как у образца. Помогло сгенерировать позу заново с образца
  и добавить: `Keep his antlers exactly as in image 1: the same large, long, curved antlers with the same branching
  tines, the same shape and the same size.`
- **Хвост, обрезанный краем картинки**: расширить холст прозрачным полем и обвести красным пустую область, где
  его надо дорисовать.
- **Количество пальцев** модель считает плохо. Даже с правкой по красному кругу пальцы на лапах часто остаются
  прежними, поэтому результат нужно проверять при увеличении.
